INSTALL THE REVISION
1. Open the relevant LLM@CIB project. REPLACE its old Instructions field with the full content of 01_Project_Instructions.txt. Attaching this file is not equivalent to setting project instructions. Do not append v2 below v1.
2. Start a fresh chat for the first v2 trial so previous conflicting prompts or bad draft examples do not control the task. Keep useful actual evidence and reference configurations available.
3. 02_Task_Prompts.txt contains complete selectable task blocks. Copy ONE prompt, not the whole menu, into the chat or a Favorite Prompt. These now repeat essential task/output rules so they are useful outside the project as well. Normal pasted input inside the project should still trigger the default task.
4. Reference_Templates are optional forms for facts, not required homework. Fill only relevant fields with verified information. Attach actual reference configurations and evidence; do not upload empty forms as factual knowledge. Start using each project with the evidence you already have.
5. Worked_Examples are fictional behavior demonstrations and local acceptance cases. Never treat their values as live site facts. Core instructions are self-contained; uploading examples is optional.
6. Migration now includes the continuous Cisco reference format in the MAIN instructions and generation/repair prompts. The separate structure file is only a standalone reminder; do not append it again.
7. Use one chat per investigation/change/migration. Maintain site continuity with a reviewed Current_Status file. Ask for HANDOFF, review the proposed text and replace the project file if the app cannot save it itself.

01 Daily Network Analysis: paste logs, show output, config or a question. Environment overview/standards help but are not mandatory.
02 Upgrades: actual labelled PRE and POST, known expected changes and required checks. OLD/NEW mapping for replacement. Short output still compares exact objects.
03 Migration: matched reference Juniper/Cisco pair + target Juniper + actual target hardware/port plan. Full configuration generation needs full source coverage; stage reference analysis first if useful.
04 Workplace Writing: paste the rough message. No reference file needed.
05 Network Notes Organizer: paste/attach actual notes. Add an existing reference or progress ledger only for merge/continuation work.
06 Argentina / 07 Mexico / 08 Colombia / 09 Brazil: current incident evidence; add dated topology/circuit/configuration/status knowledge as available. Essential troubleshooting and validation rules are included directly.

MODELS / INPUTS
Use the text engineering model you already selected (GPT-OSS) as the starting point. These prompts do not assume a special model version, context limit, execution tool or reasoning setting. Use a model/input route documented by your app for screenshots; verify extracted values. Writing and notes prompts can be tried with your Mistral or Gemma options using the same acceptance cases.
RAG may supply excerpts rather than full files. A stronger prompt cannot manufacture omitted evidence. If a comparison/conversion is incomplete, provide the missing named section, a smaller complete text input, or use an available parser. Never accept a whole-file completion claim just because a table looks finished.
Do not assume cross-chat history access, automatic file updates or that moving chats to projects hides the global chat list. No upload-count or instruction-field limit is assumed by this pack. If the app rejects the instruction length, record its actual limit before making a shorter variant; do not truncate silently.
